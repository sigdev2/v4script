# Development

How to work on v4script itself. Contribution rules are in
[CONTRIBUTING](../CONTRIBUTING.md); rules for AI agents in
[AGENTS](../AGENTS.md).

## Building

```
cmake -S . -B build -DCMAKE_PREFIX_PATH=<Qt>/<kit> -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel
ctest --test-dir build --output-on-failure
```

Qt 6.4.1 is the reference version. On Linux the tests run without a
display. The scripts are resources: after changing a `.js` file, build
again (CMake tracks the files; with `V4SCRIPT_MINIFY_JS=ON` configure
again).

The Node.js tools need their packages once:

```
cd tools
npm ci
```

## Branches and commits

 - `master` - releases only; every commit on it is a released version
   with a tag `vX.Y.Z`.
 - `dev` - development. Work happens on `dev` (or short-lived branches
   merged into it); a release merges `dev` into `master`
   (see [releasing](releasing.md)).
 - Commit messages, code comments, identifiers, documentation and the
   README are **in English**.
 - A commit keeps the tests passing and updates the documentation it
   affects.

## Code style

The rules are in [StyleGuide.CPP.md](../StyleGuide.CPP.md) (C++17:
naming, classes, formatting, headers, implementation, lambdas, Qt,
threads, comments) and [StyleGuide.JS.md](../StyleGuide.JS.md) (ES2016:
the language level, file structure, naming, formatting, V4 limits,
generated code). This section is about the tools.

 - C++ is formatted with **clang-format 15** (the one bundled with Qt
   Creator) and the repository [.clang-format](../.clang-format):
   `clang-format -i -style=file <files>`. Other versions format some
   constructs differently; `.clang-format` must stay readable by
   version 15.
 - JavaScript has no formatter: the rules are followed by hand.
   [tools/minify.mjs](../tools/minify.mjs) checks the depth of
   expressions. Node.js accepts syntax that V4 rejects, so
   `LanguagesTest` is the final check that a script loads in V4
   ([testing](testing/README.md)).

## Third-party bundles

`js/vendor/` is generated by
[tools/build-bundles.mjs](../tools/build-bundles.mjs) from versions pinned in
[tools/package.json](../tools/package.json) and the script (Skulpt and
Perlito5 at fixed commits, downloaded from GitHub):

```
node tools/build-bundles.mjs            # all
node tools/build-bundles.mjs lua php    # some
```

The bundles are not minified, so that they can be read; releases minify
them with the rest of `js/` (see below). The build is reproducible: the
same versions give the same bytes. Patches of third-party code and the
reasons are in
[vendor](internals/vendor.md#building-the-bundles); every patch checks that
the original text is still there. After updating a bundle: run the samples
of the language, update the versions in [languages.json](../languages.json),
[THIRD_PARTY_NOTICES](../THIRD_PARTY_NOTICES.md) and the README.

## Minified scripts

[tools/minify.mjs](../tools/minify.mjs) writes a minified copy of `js/`
(whitespace and local names; the syntax stays ES2016, a file keeps the
value of its last expression) and checks that no expression is deeper than
the V4 compiler can take. Embed it with `-DV4SCRIPT_MINIFY_JS=ON` (minifies
at configure time) or `-DV4SCRIPT_JS_DIR=<directory>`. The resources shrink
from 11.1 MB to 5.6 MB. Run the tests with the minified scripts before a
release: V4 has crashed on code shapes that only the minified scripts had.

## The playground

The site of the playground is built from [web/](../web) and `js/` by
[tools/build-site.mjs](../tools/build-site.mjs) and deployed to GitHub Pages
from `master`; `node tools/build-site.mjs --serve` builds it and serves it
locally. See [playground](playground.md). A change of the host layer or of
the scripts of a language should keep the examples of the playground
running: `node tools/run-samples.mjs <language> --examples` (CI runs it).

## Reference implementations

The translated languages are checked against real implementations used as
black boxes (their output, not their sources): gcc, JDK, gforth, QB64-PE,
Free Pascal, wabt and the WebAssembly spec tests, chibi-scheme
([testing](testing/README.md#samples)). On Windows they run in WSL. Code of
v4script is written from the behavior and the published specifications;
do not copy code of those implementations unless its license allows it and
it is listed in [THIRD_PARTY_NOTICES](../THIRD_PARTY_NOTICES.md).
