# JavaScript code style

Version: 0.0.1

Rules for the JavaScript code of v4script: everything in [js/](js) except `js/vendor/`, and JavaScript in C++ string literals (the timers in [src/Runtime.cpp](src/Runtime.cpp)). `js/vendor/` is generated by [tools/build-bundles.mjs](tools/build-bundles.mjs) and is not edited by hand. The tools in `tools/*.mjs` run in Node.js and the playground in `web/` runs only in browsers: they are not bound by these rules and use `const`, `let` and arrow functions. The C++ style is described in [StyleGuide.CPP.md](StyleGuide.CPP.md).

The code runs in the JavaScript engine of Qt 6.4 (V4) inside a `QJSEngine`. There is no build step: a file is embedded into the resources and runs as it is (or minified by [tools/minify.mjs](tools/minify.mjs), which keeps the syntax). There is no formatter for JavaScript either, so the rules of section 4 are followed by hand.

Every rule comes with an example. Where the reason is not obvious, a short note explains why the rule exists.

---

## 1. Language level

### ES2016 and nothing newer

V4 in Qt 6.4 implements ECMAScript 2016. A construct of a later version is a syntax error, and the whole file fails to load:

- `async` / `await`;
- `...` in an object literal: `{ ...defaults, size: 10 }`;
- `?.` and `??`;
- the regular expression flag `s`, named groups `(?<name>...)` and lookbehind `(?<=...)`.

Library functions of later versions (`Object.fromEntries`, `Array.prototype.flat`, `String.prototype.replaceAll`, `Promise.prototype.finally` and the like) are missing in V4. [js/host/compat.js](js/host/compat.js) adds them for the interpreters of other languages; the code of v4script does not use them.

### A subset of ES2015

From ES2015 the code takes only what does not change the general look of the code: collections, symbols, generators, promises, typed arrays. The new syntax of declarations and functions is not used:

| Used                                                             | Not used                                      |
| ---------------------------------------------------------------- | --------------------------------------------- |
| `var`                                                            | `let`, `const`                                |
| a function expression `function (item) { ... }`                  | an arrow function `(item) => ...`             |
| a constructor function and `prototype`                           | `class`                                       |
| string concatenation `'Row ' + row`                              | a template literal `` `Row ${row}` ``         |
| a check for `undefined` in the body, `arguments`                 | default parameters, `...rest`, `...` in a call |
| `for (var index = 0; ...)`, `forEach`                            | `for (... of ...)`                            |
| `var first = pair[0];`                                           | destructuring `var [first, second] = pair;`   |
| `key: function (value) { ... }` in an object literal             | a shorthand method `key(value) { ... }`       |
| `Map`, `Set`, `Symbol`, `function*` and `yield`, `Promise`, `Uint8Array` | -                                     |

```js
// Wrong: ES2015 syntax that the code does not use
const cells = rows.map((row) => `${row.name}: ${row.value}`);

// Right:
var cells = rows.map(function (row) {
    return row.name + ': ' + row.value;
});
```

**Why:** all of the code is written the same way, and a mix of `var` and `let` or of functions and arrows reads worse. This set of constructs is proven on V4 by the tests, and its limits (section 6) are easier to respect in plain code.

### Strict mode

The first statement of the wrapping function of a file is `'use strict';`. It applies to the whole code of the file.

**Why:** an assignment to an undeclared variable becomes an error instead of creating a global variable that every language of the engine would see.

## 2. File structure

### The header comment

A file starts with a comment: what it does, what it receives and what it returns, where the contract with C++ or with other files is described.

```js
// Host layer: builds the `host` object that every language adapter receives.
//
// The file evaluates to a factory `function (bridge, global)`. The bridge is
// the native side - the C++ HostBridge (src/HostBridge.cpp) or a plain
// object in tools/run-samples.mjs. The contract is described in
// docs/internals/host.md.
(function (bridge, global) {
    'use strict';
    ...
})
```

### A file is a function expression

There are no modules: all the code of a file lies in one function, and only what the function gives out is visible outside. Files are of two kinds:

- **A factory.** The file is the expression `(function (host) { ... })` without a call. C++ evaluates the file, gets the function and calls it with its own arguments (`js/host/host.js`, `js/host/canvas.js`, the adapters in `js/adapters/`). The factory returns an object with what the caller needs.
- **An extension of a namespace.** The function is called at once - `})(globalThis);` - and adds its parts to a shared object (the files of the translator add to `globalThis.V4ScriptTranslator`). A second load of the file changes nothing: a check stands at the beginning.

```js
// A factory: what to give out - at the end, the keys are written explicitly
(function (bridge, global) {
    'use strict';

    function run(code) {
        ...
    }

    return {
        host: host,
        run: run
    };
})

// An extension of a namespace: a second load does nothing
(function (global) {
    'use strict';

    var T = global.V4ScriptTranslator;
    if (T.session)
        return;
    T.session = true;
    ...
})(globalThis);
```

**Why a factory without a call:** the arguments (`bridge`, `host`) exist only on the C++ side, and they do not get into the global object - the programs of the languages cannot reach them.

### Sections

Parts of a big file are separated by a section comment `// --- Name` with empty lines before and after it. The constants and variables of a section are declared at its beginning.

```js
    // --- Output

    var writers = [];

    function writer(stream) {
        ...
    }

    // --- Input
```

## 3. Naming

### Cheat sheet

| What is named                                          | Style                         | Example                              |
| ------------------------------------------------------ | ----------------------------- | ------------------------------------ |
| Constructor functions                                  | UpperCamelCase                | `Parser`, `Environment`, `BasicError` |
| Functions, methods, variables, parameters, object keys | lowerCamelCase                | `defaultFormat`, `flushAll`          |
| File-level constants and tables                        | SCREAMING_SNAKE_CASE          | `STREAMS`, `TWO_CHAR`                |
| Short aliases of namespaces                            | one or two capital letters    | `var T = global.V4ScriptTranslator;` |
| `this` for a nested function                           | `self`                        | `var self = this;`                   |
| The variable of an exception                           | `error`                       | `catch (error)`                      |

### Full words

Names are full words: `index`, `value`, `error`, `column`, not `i`, `v`, `e`, `col`. One-letter names are allowed only for the aliases of namespaces (`T`, `J`, `S`), which are declared at the beginning of the file.

```js
for (var index = 0; index < values.length; ++index)
    parts.push(format(values[index]));
```

### Private means local

A leading underscore (`_cache`) is not used. What is not needed outside stays a local function or variable of the file and does not get into the returned object or the namespace.

**Why:** an underscore hides nothing - a field with it is as visible to the programs as any other. A local variable of the wrapping function is really unreachable from outside.

## 4. Formatting

### Indentation, line length, quotes

- Indentation is 4 spaces; tabs are not used.
- A line is up to 120 characters long. A longer one is allowed only for a row of a data table that a break would make harder to read.
- Strings are in single quotes; double quotes go inside a string: `'Expected "end"'`.
- A semicolon ends every statement; automatic insertion is not relied on.
- Spaces go around binary operators, after a comma and inside the braces of an object literal: `{ op: 'fill', range: address }`. There are no spaces inside square brackets: `[first, second]`.
- An anonymous function has a space after `function`: `function (value)`; a named one does not: `function format(value)`.
- A loop counter is incremented with the prefix `++index`.
- Two or more empty lines in a row are not written; one empty line goes between functions.

### Braces

- `{` always goes at the end of the line - for functions too (unlike C++).
- A body of `if`, `else`, `for`, `while` of one statement is written without braces, on the next line, indented.
- If at least one branch of an `if` / `else` needs braces, all branches get them: `} else {`.
- `else`, `catch` and `finally` are written on the same line as the closing brace.

```js
function check(error) {
    if (error)
        throw new Error(error);
}

function finishLine(writer, text) {
    if (text.length > 0) {
        writer.write(text);
        writer.write('\n');
    } else {
        writer.flush();
    }
}
```

A short function argument of one statement is written on one line:

```js
var names = cells.map(function (cell) { return cell.name; });
```

### Breaking long lines

- An operator (`&&`, `||`, `+`) stays at the end of the line; the continuation gets an extra indentation of 4.
- The parts of the ternary operator `?` and `:` move to the beginning of the next lines, as in C++.

```js
return token.type === 'newline' || token.type === 'eof' ||
    (token.type === 'op' && token.value === ':');

var caption = range.isEmpty()
    ? 'Empty range ' + range.address
    : 'Range ' + range.address;
```

### `switch`

`case` is written at the level of `switch`, the body is indented. If a `case` declares a variable, its body is put into braces: `{` at the end of the line with `case`, `}` at the level of `case`.

```js
switch (node.kind) {
case 'number':
    return String(node.value);
case 'sum': {
    var left = expression(node.left);
    var right = expression(node.right);
    return left + ' + ' + right;
}
default:
    throw new Error('Unknown node: ' + node.kind);
}
```

**Why the braces:** a `var` is visible in the whole function anyway, but the braces show which `case` the variable belongs to and keep it from being used in a neighboring `case` where it is not set.

## 5. Values, objects and errors

### Comparisons

- Comparisons are only strict: `===` and `!==`.
- The only exception is the check for "`null` or `undefined`" at once: `value == null`, `value != null`.
- A type is checked with `typeof`: `typeof callback === 'function'`.

**Why:** a loose comparison converts types (`'' == 0`, `'1' == 1`), and an error in the data goes unnoticed.

### Properties and dictionaries

- An own property is checked with `Object.prototype.hasOwnProperty.call(object, key)`, not with `object.hasOwnProperty(key)`: an object without a prototype or with a field `hasOwnProperty` has no such method.
- A dictionary with arbitrary keys is a `Map` or `Object.create(null)`. A plain literal `{}` already has the keys `constructor`, `toString` and others from its prototype - and the names of a program (a Go function `constructor`, a Forth word `toString`) must not collide with them.

```js
var cache = Object.create(null);
if (!Object.prototype.hasOwnProperty.call(cache, name))
    cache[name] = load(name);
```

### Constructors and prototypes

- An object with behavior is a constructor function with its methods in `prototype`. All fields are set in the constructor, including those that are `null` at first.
- Inheritance is a call of the parent through `call` and `Object.create` for the prototype; `constructor` is restored.
- Properties with `get` / `set` are defined once on the prototype with `Object.defineProperties`, not on every object (see section 6).
- A nested function that needs `this` gets it through `var self = this;`.

```js
function Parser(tokens, source) {
    T.Parser.call(this, tokens, source);
    // The procedure being parsed (null - the module level).
    this.inProcedure = null;
    this.dataItems = [];
}
Parser.prototype = Object.create(T.Parser.prototype);
Parser.prototype.constructor = Parser;

Parser.prototype.expectKeyword = function (word) {
    if (!this.isKeyword(word))
        this.fail('Expected: ' + word);
    return this.next();
};
```

### Errors

- An error object is thrown, not a string: `throw new RangeError('Wrong row: ' + row);`. The type follows the meaning: `TypeError` for an argument of a wrong type, `RangeError` for a value out of range, `Error` for the rest; errors of a language (`T.LanguageError` and its descendants) for what the program of the language did wrong.
- The texts of errors are in English.
- The variable of a `catch` is named `error`. An empty `catch` is allowed only when the failure is expected and a fallback follows right after the block.

```js
try {
    var text = JSON.stringify(value);
    if (text !== undefined)
        return text;
} catch (error) {
}
return String(value); // JSON does not take circular references
```

## 6. Limits of V4

V4 of Qt 6.4 has bugs that crash the process or silently spoil the result. The full list with explanations is [V4 pitfalls](docs/internals/v4-pitfalls.md); below is what concerns any code.

- **Expression depth.** The V4 compiler walks an expression by recursion without a stack check: a chain of thousands of `+` crashes the process. A long text is collected into an array and joined with `join`.
- **`WeakMap`** with thousands of keys crashes the process during garbage collection. A `Map` that is cleared is used instead, or the data is kept on the objects themselves.
- **A data property must not be redefined as `get` / `set`** on many objects (`Object.defineProperty(object, 'node', { get: ... })` after `object.node = ...` in the constructor): V4 crashes. Such properties are defined once on the prototype.
- **`Function.prototype.toString`** returns `[native code]` for every function: the text of a function is not relied on.
- **`return` with an assignment.** In strict code V4 runs `return f(...)` as a tail call even where it is not one: `return a.b = c ? d : f()` loses the assignment. The value goes into a temporary variable first.
- **An array after `shift`** breaks with `sort` and `splice` (elements repeat or vanish): a queue is rebuilt as a new array.
- Typed arrays have no `sort`.

```js
// Wrong: thousands of + in one expression
var html = '<tr>' + cells[0] + '</tr>' + '<tr>' + cells[1] + '</tr>' + ...;

// Right:
var rows = [];
for (var index = 0; index < cells.length; ++index)
    rows.push('<tr>' + cells[index] + '</tr>');
var html = rows.join('');
```

## 7. Comments and strings

- Comments are only line comments `//`. Block comments `/* */` and JSDoc are not used.
- Comments are in English, like everything in the repository.
- A comment says what the code cannot: why it is done exactly this way, side effects, what the caller must do. Obvious comments are not written (see section 9 of [StyleGuide.CPP.md](StyleGuide.CPP.md)).
- Knowledge that concerns several files (a contract with C++, the design of a translator) is described in [docs/internals](docs/internals/README.md), and the code keeps a pointer to it.
- Messages of errors and warnings are in English.

```js
// The host may give its own format at any time.
function format(value) {
    return bridge.hasFormat && bridge.hasFormat() ? String(bridge.format(value)) : defaultFormat(value);
}
```

## 8. Generated code

The translators build the JavaScript of a program as a tree (`J.*` in [core/compiler.js](js/translator/core/compiler.js)), never by string concatenation: the tree keeps the lines of the source, so errors and the stack point to the lines of the program, and the depth of every expression is checked before V4 sees it (the translator refuses expressions deeper than 250 levels).

```js
// Wrong: the text of the code is glued together
var code = 'var ' + name + ' = ' + value + ';';

// Right: a node of the tree, tied to the line of the source
var node = J.at(J.var_(name, J.num(value)), line);
```
