# AGENTS.md

Instructions for AI agents working on v4script - a C++17 / Qt 6 library
that runs many programming languages inside the Qt JavaScript engine (V4).

## Language of the project

**Everything in this repository is in English, strictly**: commit
messages, code comments, identifiers, documentation, the README, test
names, error and log messages. Non-English text appears only as test data
(UTF-8 strings that check Unicode handling).

## Start here

1. [docs/README.md](docs/README.md) - the index of the documentation.
   Read the index, then only the sections you need.
2. [docs/internals/README.md](docs/internals/README.md) - architecture and
   the manifest; the page of the language you touch in
   [docs/internals](docs/internals).
3. [docs/internals/v4-pitfalls.md](docs/internals/v4-pitfalls.md) - bugs
   and limits of V4 that every script must respect. Read it before
   changing JavaScript.
4. [StyleGuide.CPP.md](StyleGuide.CPP.md) and
   [StyleGuide.JS.md](StyleGuide.JS.md) - the mandatory code style.
5. [docs/development.md](docs/development.md) - layout, tools;
   [docs/testing/README.md](docs/testing/README.md) - tests and samples.
6. [TODO.md](TODO.md) - the approved order of new languages, decisions for
   them and known gaps.

## Branches and commits

 - Only two long-lived branches: **`master`** - releases, every commit is
   a tagged version; **`dev`** - development. Do not create other
   permanent branches.
 - Work on `dev`. A release merges `dev` into `master` with
   `git merge --no-ff dev` ([docs/releasing.md](docs/releasing.md)).
 - Commit, merge, tag or push only when the user asks.
 - One logical change per commit, with the tests passing and the
   documentation updated.

## Build and test

```
cmake -S . -B build -DCMAKE_PREFIX_PATH=<Qt>/<kit>
cmake --build build --parallel
ctest --test-dir build --output-on-failure
```

Qt 6.4.1 is the reference version; a Linux build of the tests and the
examples is required, Windows when C++ changes. Quick checks of the scripts
run in Node.js: `node tools/run-samples.mjs <language>` (needs
`npm ci` in `tools/` once). Node is more forgiving than V4: the final check
is `LanguagesTest`. Before a release, run the tests with
`-DV4SCRIPT_MINIFY_JS=ON` too.

## Code rules

 - C++: C++17, [StyleGuide.CPP.md](StyleGuide.CPP.md), clang-format **15**
   with [.clang-format](.clang-format) (newer versions format some cases
   differently).
 - JavaScript in `js/`: [StyleGuide.JS.md](StyleGuide.JS.md) - ES2016
   only, IIFE files with `'use strict'`, `var` and `function`; no build
   step. Respect [V4 pitfalls](docs/internals/v4-pitfalls.md): no deep expressions
   (the V4 compiler recursion is unguarded), no `WeakMap` with many keys, no
   per-object redefinition of data properties as accessors, no reliance on
   `Function.prototype.toString`.
 - Comments say only what the code cannot: why, side effects, obligations
   of the caller. Knowledge across files belongs in `docs/internals`.
 - `js/vendor/` is generated by `tools/build-bundles.mjs`: never edit it by
   hand; patches go into the build script.
 - Source files are UTF-8 without BOM with LF line endings.
 - Do not remove functions that only tests use.

## Licensing

 - The project is MIT. Never copy code from implementations under
   incompatible licenses (GPL, LGPL: gforth, Free Pascal, glibc, OpenJDK,
   GCC…) - not even a few lines. Reference implementations are black
   boxes: compare their **output**, write the code from observed behavior
   and specifications. The Pascal number formatting, `Graph` and the
   Mersenne Twister were rewritten this way; do not read the sources of
   Free Pascal.
 - Code under a compatible license (MIT, BSD, Apache-2.0) may be used with
   attribution in [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)
   (QB64-PE for BASIC algorithms and the 8x8 font).
 - Samples and examples are own programs, never listings from books.

## Working method for a language

 - Samples in `tests/samples/<language>/` with expectations in trailing
   comments (`Input:`, `Output:`, `Value:`, `Error:`, `Line:`); iterate in
   Node (`--run file --dump` shows the generated JavaScript), then run
   `LanguagesTest` in V4.
 - Take expected output from the reference implementation (gcc, JDK 19,
   gforth 0.7.3, QB64-PE 4.7.0, fpc 3.2.2, wabt 1.0.27, chibi-scheme 0.9.1),
   e.g. in WSL or a Linux container; write samples so that the reference
   can run them too (a `main`, no undefined behavior).
 - Multi-unit behavior (declarations shared by units, units run again) is
   part of every language: test it.
 - Write patch scripts and test programs to files with an editor tool;
   shell heredocs may mangle backslashes.

## Documentation

Documentation is part of every change: **any change to code, build,
formats or behavior updates the documentation in the same change** -
add new facts, correct outdated ones, delete what no longer exists. Then
check that the indexes still describe their sections and that relative
links resolve.

 - [docs/languages](docs/languages/README.md) - for program authors:
   behavior, limits, differences from the reference implementation, with
   examples that run.
 - [docs/embedding](docs/embedding/README.md) - for application
   developers: the C++ API and the build.
 - [docs/internals](docs/internals/README.md) - for developers: design
   decisions, file maps, knowledge not visible in a single file. As short
   as possible; do not retell code.
 - [README.md](README.md) - overview, the language table with versions,
   planned languages, third-party projects, license.
 - [TODO.md](TODO.md) - plans and gaps.
 - Every directory of `docs/` has a `README.md` index; keep it in sync.

## Versions

The project version is in [VERSION](VERSION); every language has its
`version`, `dialect` and `implementationVersion` in
[languages.json](languages.json). Translated languages carry the version of
v4script. Update the README table when a version changes.
